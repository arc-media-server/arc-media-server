# #350: one owned import, atomic profile preparation and retained results

Reproduced three import findings: invalid mappings left earlier new profiles behind; a running two-hour-old import was evicted by the one-hour session sweep despite a three-hour job limit; and 64 concurrent Run requests admitted four jobs. Reserve the session before preflight so only one request owns admission. Validate all known source accounts/targets, then create requested profiles in one transaction. A later invalid target or generated-name collision rolls back all new profiles. Preserve the existing alternate-name convention. Unknown source accounts are rejected.

Running/preparing sessions remain pollable. Completed/failed job results receive a full hour of retention from completion. A slow earlier Plex login poll cannot rewind a later stage; server selection also reserves the session and refuses changes during active work. Public stage names and successful response shapes remain unchanged.

Accepted jobs use the server root context with the existing three-hour cap and join the API worker group before the store closes. Listener reconfiguration does not cancel an accepted import. Server shutdown cancels source work; a later import can merge already imported watch state without resetting Arc. Jobs and sessions remain in memory, not a durable resume queue. This change does not claim that all other Arc background workers/FFmpeg children have been joined; broader shutdown is another finding.

API integration uses the same WorkContext/Workers and main worker-group foundation as #377. Merge those shared pieces once, preserving both workers. Import profile preparation and the whole accepted job also hold the shared catalog-work lease from #365; admission while restore/delete maintenance is reserved returns 503/Retry-After: 3 before creating profiles. The exact catalog gate foundation is reused, not a second lock. A further red regression reproduced both maintenance admitting during an import and new profiles being created during reserved maintenance, then passed with the lease. Client behavior and additive error statuses are documented in docs/IMPORT-JOB-HANDOFF.md. No media changes or web implementation.

Diagnostics: one start and one outcome with source, completed-account count and duration. Source-read failures and database-write failures have safe operation/reason labels. Raw upstream errors can contain credential-bearing URLs, so they are not copied into logs or top-level session/activity error text. Expected root cancellation is an informational interrupted outcome. No per-item/info flood, secret, URL/query, request body or SQL-argument logs. Detailed existing lists-result errors and non-job sign-in/connection flows are outside this change's diagnostic scope.

Regressions use temporary stores, held/cancelled in-process sources and synchronized concurrent requests. An initial context.Err gate did not reproduce concurrency; its passing baseline log is retained. The synchronized-body test then reproduced four admissions. Fixture fixes (non-nil source, fresh retry body) are retained separately from genuine regression evidence. Tests also cover atomic rollback, name fallback, cancellation/join, retention and URL/key privacy. No owner data/keys, production systems or persistent Arc server.

Final validation after adding catalog exclusion: focused admission/profile/lease/lifecycle/privacy checks, API-doc generation, Go vet, full Go suite and serial API/store/importer/main race checks passed (API 298.525s; store 246.616s; importer 12.675s; main has no tests). Earlier pre-lease validation also passed and is retained separately; it is not substituted for the final head's evidence. Generated OpenAPI adds only run 503/server-selection 409 errors; the v1 contract has no diff. Broader bounded shutdown of every other worker remains open.
