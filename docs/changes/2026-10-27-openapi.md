# OpenAPI description (#139, step 1, 27 October 2026)

`go run ./tools/apidoc` now also writes `docs/openapi.json` (OpenAPI 3.1), generated from the
code rather than written by hand: routes, access (anyone/profile/admin) and descriptions as for
API.md, plus what internal/api's handlers do, found by type-checking them (go/types with the
compiler's export data; no new module): the JSON type each decodes from the body, raw uploads,
the types and statuses each answers with, file/stream responses, the errors each can answer
with (including from helpers it calls) and the query parameters it reads. Go types become JSON
schemas from their json tags; shared named types are components.

The server serves it at `GET /api/openapi.json` (and `/api/v1/openapi.json`) for anyone, embedded
by the `ams/docs` package. `TestOpenAPIUpToDate` fails when it's stale, and generation fails if
a handler answers in a way the generator can't see, so new endpoints are documented. It passes
Redocly's recommended lint (warnings only: no licence yet; four public endpoints have no 4xx).
Next steps: a /docs page in Arc and a published docs website from the same file.
