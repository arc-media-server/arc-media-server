# The /api/v1 promise is now enforced by a test

Before starting the Android TV app, the v1 API (`/api/v1/...`) has to stay compatible: docs/API.md
promises endpoints and fields aren't removed or changed incompatibly within v1. Two of today's
changes broke that, harmlessly since no app exists yet:

- **Recommended rows** (#283) replaced `title` with `type` and parameters. Rows now carry both: the
  `type` (which the web app translates) and an English `title` for apps that just show it.
- **Fix Match** (#281) answered shows with 202 instead of 200. It now answers 200 for shows too,
  still with `match_task_id` for the background part.

**The contract.** `docs/api-v1-contract.txt` lists every endpoint, success status and response
field (with its JSON type), flattened from the generated OpenAPI. `go run ./tools/apidoc` only adds
to it. `TestV1ContractKept` fails when the code no longer answers with a line in it, or when a new
line hasn't been recorded. Removing a line by hand is how a deliberate break is made, so it shows
in review. The Recommended response now has a named type, so its row fields are in the contract.

Limits: request bodies and query parameters aren't covered (removing an accepted field would break
apps too); responses the generator sees only as free-form maps are recorded as "any" without
their fields.
